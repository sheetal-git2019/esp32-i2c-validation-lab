Traceability

Test plan at a glance.

Each test is tied to an observable criterion. Fault tests are expected to fail at the interface level; the pass condition is correct fault detection and reporting.

Test ID Test type Stimulus Expected result Status
TC-01 Functional 0x76 register read at 400 kHz Three bytes, all ACKs, ≤ 10 ms Pass
TC-02 Negative Request 0x77 (wrong address) NACK detected and logged Pass
TC-03 Negative Hold SDA low before START Timeout and bus recovery path Pass
TC-04 Boundary 100 kHz clock setting Timing violation is flagged Pass
TC-05 Regression Correct address restored Nominal read passes again Pass

Defect investigation

One defect, closed with evidence.

A concise debug narrative is more valuable to a hiring manager than a long list of happy-path screenshots.

01

Symptom

Sensor initialization returns no data, and the serial log records an I²C acknowledge failure.

02

Isolation

The simulated trace stops after 0x77(W). The configured peripheral model listens on 0x76.

03

Root cause

A firmware configuration constant used the alternate BME280 address with the address-select pin modeled low.

04

Resolution

Correct the address, repeat the nominal test, and retain TC-02 as a regression test for fault handling.

Automation evidence

UART logs, summarized in Python.

The repository includes a dependency-light parser and a simulated log fixture. With hardware later, the fixture can be replaced with captured serial output.

Included utility

Turn raw logs into test evidence.

python tools/analyze_logs.py data/simulated_uart_log.csv
